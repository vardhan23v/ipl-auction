# IPL Mega Auction — notes for agents

- Stack: Next.js 16 App Router + TS + Tailwind 4 on **Vercel** (region hnd1, same as the Supabase project in ap-northeast-1); Prisma 6 + **Supabase Postgres**; **Supabase Realtime** for live updates; **Supabase Auth** for sign-in. No custom server, no Socket.IO, no in-memory timers — everything must work in short-lived serverless functions. Dark "stadium" theme in `src/app/globals.css` (gold money, red live, purple RTM). Mobile-first: every page must work at 375px.
- **Multi-room (open-source, crickauction-style):** anyone signs in (Google or guest) and creates a *room* (`Room`, 6-char `code`). Each room has its own 10 franchises, 547-player IPL 2026 pool (`prisma/data/players.json`, validate with `npx tsx scripts/check-pool.ts`), settings and live state. Room URLs: `/r/CODE` (lobby), `/r/CODE/live|display|owner|host|players|squads|rtm|history|analytics|results|manage/*`. Room APIs live under `src/app/api/rooms/[code]/...`; `roomGuard(code, "host"|"member"|"any")` in `src/lib/api.ts`; `loadRoomPage()` in `src/lib/room-page.ts` for pages.
- Money is integer **lakhs** everywhere (₹1 Cr = 100). Format with `money()` from `src/lib/format.ts`.
- All auction mutations go through `src/server/auction-engine.ts`: `withLock` = one Postgres transaction + `pg_advisory_xact_lock(hashtext(roomId))`; inside it use `q()` (the transaction client), `seq([...])` instead of `prisma.$transaction([...])`, and `broadcast()` (queued, published after commit). Clock/RTM deadlines are settled by `settleDue()` (before every action, on GET /state, on POST /tick from clients at zero). Never mutate purses/squads from routes directly; host player assignment is the one exception and must keep `overseasCount`/`rtmUsed` consistent. Realtime channel per room is `room:CODE` (`src/lib/realtime-server.ts` publishes, `src/lib/realtime-client.ts` `roomBus(code)` subscribes). Raw SQL must quote Postgres identifiers (`"Player"`, `"queueOrder"`).
- Bidding rule (crickauction logic): ONLY the manager who claimed a franchise (`Team.ownerId`) can bid, and only for that franchise, from `/r/CODE/live` (renders `OwnerRoom` when the viewer owns a team). The host never bids for anyone; unclaimed franchises sit out and are never offered RTM. Enforced in `placeBid` / `rtmActionUnlocked` / `canRtm`.
- RTM: `Player.previousTeamId` is the fixed RTM list; states `RTM_OFFER → RTM_RAISE → RTM_MATCH`; owners act via `POST /api/rooms/[code]/rtm`; bids via `POST /api/rooms/[code]/bid`.
- Roles: platform `User.role` is ADMIN or USER. Inside a room: HOST (`Room.hostId`), OWNER (`Team.ownerId`), SPECTATOR (`RoomMember`). `getRoomAccess()` in `src/lib/room.ts` resolves them. Route guards for `/admin`, `/rooms`, `/r/:code/host|manage|owner` live in `src/proxy.ts`.
- Sign-in: Supabase Auth — Google, anonymous guests (name in `user_metadata.name`), admin email+password (seeded by `npm run db:seed`). `getSession()` in `src/lib/auth.ts` returns `{ user: { id, name, image, role, isGuest } }` and upserts the `User` profile (id = Supabase user id). `src/proxy.ts` refreshes the session cookie. Claim a franchise with `POST /api/rooms/[code]/claim`. All tables have RLS on with no policies — only Prisma (server) touches data; never query tables from the browser.
- Local dev uses the Supabase project in `.env` (see README). Don't push to GitHub from an agent — the user pushes.
